### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `<host-worktree-directory>/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and the newest chat that touched it, then suggests a bucket. The conversation record scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user, or from the host's session list when it has one, and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the conversation records and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, conversation records are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when no session list shows their names. Use effort and speed controls only when the host exposes them, per the Subagents section.
4. Preserve local data. The audit holds tracked edits, untracked and ignored files, locked worktrees, and failed queries. Inspect every held path. Give each local file or directory an explicit disposition before removal. Preserve unknown data and ask the user when its disposition is unclear. Only proven reproducible caches or scratch created by this run can be treated as disposable. A Git ignore rule or an untracked filename does not prove that. Clean, merged, and not-in-use worktrees can proceed under the existing authorization.
5. Prune the confirmed set. Recheck usage and the complete local-file inventory immediately before removal. Use ordinary `git worktree remove <path>` for each confirmed path. If removal refuses, stop and inspect the path again. Do not escalate to forced removal or recursive deletion. Any separate cleanup of disposable files requires its own confirmed disposition and authorization. Branch refs survive. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: platform build caches such as Xcode `DerivedData` and `iOS DeviceSupport`, plus package caches such as pnpm, uv, brew, and yarn. Treat editor and application state as user data, not cache; delete it only when the user names the exact product and path and approves after inspection.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
